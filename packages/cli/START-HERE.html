No install required

pdfsuite

Compares candidate PDFs against golden references and writes a report that shows every difference on the page.

No global command, no project to set up — the only requirement is Node 20 or newer. Check with node --version.

Run it

Two PDFs — the golden one and the one to check — and a directory to write into. Tick every pair in two folders to compare two directories instead, in one run.

$ node /path/to/this/folder/dist/index.js compare ./golden/invoice.pdf ./candidate/invoice.pdf --out ./reports/invoice

The paths you pass are relative to your working directory, not to this folder. Only the path to dist/index.js points in here.

Build the command

What it writes

Three files, into the directory you named:

  • result.json — the answer. Every page with its verdict, why it changed, its measurements, and every difference with a box on each side; both files with their SHA-256; and every setting that moved the verdict.
  • report.html — the same thing to read. It opens in a browser, carries its own images, and asks nothing of the network.
  • manifest.json — every file in and out, with its size and SHA-256.

With two folders, each pair gets its own sub-folder of those three, and a result.json across them. A file in one folder and not the other fails the run and is named — a document that stopped being produced is the regression most worth catching.

When the pages do not line up

A page added to the candidate and a page dropped from the golden look the same to any tool — so you say which it was. --pages "1:1,2:-,3:2,-:4" reads as: page 1 meets page 1, golden page 2 has no partner, golden 3 meets candidate 2, and candidate 4 is new. Anything you do not mention is paired 1:1, and nothing is guessed.

What you get

FileWhat it is for
result.jsonThe answer. Every page with its verdict and why, its measurements, and every difference with a box on each side; both files with their SHA-256; every setting that moved the verdict. Versioned, and stable enough that two runs over the same files diff cleanly.
report.htmlThe one to open. The same answer to read, with the changed pages imaged. It carries its own images and asks nothing of the network, so it travels by email.
manifest.jsonEvery file in and out, with its size and SHA-256 — so a set of reports can be checked later without trusting the folder it sits in.

The HTML is rendered from result.json and nothing else, so the page you read cannot know something the machine-readable answer does not.

What counts as a difference

A page fails if anything changed — wording, pixels, or position.

There is no tolerance to tune. The question a report answers is "did anything change?", and a knob that lets a real change be declared acceptable only hides it. A page present on one side only fails too.

Version 2.0 dropped pairs.json, the pairs command and the JUnit, CSV and Markdown reports. Two folders are now --each, and a pipeline that read JUnit reads result.json, which says more.

Exit codes

CodeMeaning
0nothing changed — and with two folders, no file is missing or new
1a page changed — or a file appeared or vanished
2the tool could not run — bad arguments, or a PDF it could not read

1 versus 2 is what lets a pipeline tell "the PDFs regressed" from "the job is broken". An empty folder is an error, never a pass.

If it does not run

Cannot find package '@napi-rs/canvas'
The node_modules folder next to dist was not copied. Copy the whole folder, not just dist.
Failed to load native binding, or a missing .node file
This folder was built for a different operating system or CPU. It carries one compiled renderer and cannot adapt. Two ways out: run npm install in this folder, if it can reach an npm registry — that replaces the renderer with the right one for your platform. Otherwise ask for a folder built for you: sh scripts/make-portable.sh --target darwin-arm64 (darwin-x64, linux-x64-gnu, win32-x64-msvc), or a lean one with --lean, which works on any platform.
macOS refuses to load it
A binary that arrived by download or shared drive rather than through npm gets quarantined. Clear the flag on the folder: xattr -dr com.apple.quarantine .
Unexpected token, or a syntax error on startup
Node is too old. node --version must be 20 or newer.

node dist/index.js --help lists every command, and node dist/index.js compare --help every flag.

A note on reading the numbers

Both sides of a comparison are rendered on the same machine, so a run is always self-consistent. Across operating systems it is not: a PDF that does not embed all its fonts falls back to the host's, so a pixel percentage from a Mac and one from Windows are not strictly comparable. Keep a baseline on one platform.
