PDF Compare — User Manual

PDF Compare checks a recreated document against its original across three dimensions — text content, visual layout, and pixels — and produces an exportable pass/fail report. This manual explains every feature and how to use it.

Side A is the original / reference document. Side B is the recreated / generated document you are checking against it. Everything runs locally in your browser — no files are uploaded.

Getting started

  1. Add the original. Drag a PDF onto the Side A · Original slot in the header, or click it to browse.
  2. Add the recreation. Do the same for the Side B · Recreated slot.
  3. Compare. As soon as both are loaded, the comparison tabs appear and the first page is analysed automatically.
Try it instantlyBefore loading your own files, click Load example invoices on the start screen. It loads a deliberately complex 6-page sample (vs a 5-page recreation) that exercises every feature — text changes, moved columns, a pixel-only chart change, a resized page, and a missing page.

Each loaded slot shows the filename and page count (e.g. 6p). Click the × on a slot to clear it and load a different file.

The interface

Once both documents are loaded, the workspace has three parts:

  • Header — the two upload slots; swap either file at any time.
  • Toolbar — the three tab buttons (Content, Layout, Report) and the page navigator.
  • Page navigator — ‹ / › to move between pages, the current page indicator, and (for multi-page documents) prev change / next change jump buttons.
Page count mismatchIf the two documents have a different number of pages, a ⚠ 6 vs 5 badge appears. Navigation still covers every page; pages that exist on only one side are handled gracefully (see Edge cases).

Content tab — what changed

The Content tab compares the text of the current page and shows exactly where each change sits.

Change highlights on the page

Both pages are rendered side by side with every change boxed, numbered, and colour-coded:

ColourMeaningShown on
RedRemoved — text present only in the original (A)Side A
GreenAdded — text present only in the recreation (B)Side B
VioletMoved — same text, different positionBoth sides

Changes list & linking

Below the pages, the Changes on this page list names each change, its type, and its location — the region (e.g. top-right) plus exact pixel coordinates, or the distance moved. Hover any highlight box, list row, or diff word and the matching items light up together, so you can trace a change from the wording to its spot on the page.

Content-match score & word diff

A content-match percentage summarises how much of the text is unchanged (green ≥ 99.9%, amber ≥ 90%, red below). The word-level diff at the bottom reads the page as running text with additions in green and deletions struck through in red.

Jump to next change

In a multi-page document, next change and prev change skip directly to the next/previous page that actually differs — including pages whose only change is visual (a recoloured header, a moved graphic) — so you never page through identical content.

Layout tab — where it moved

The Layout tab focuses on visual and positional differences. Choose a view from the control bar:

ViewWhat it shows
Side by sideThe two rendered pages next to each other.
OverlaySide B stacked over Side A with an opacity slider — slide to see B fade in over A.
Pixel diffA heat-map where changed pixels are highlighted. A badge shows the percentage of pixels that differ.

Sensitivity & anti-aliasing

In pixel-diff view, the Sensitivity slider controls how different a pixel must be before it's flagged (lower = stricter). Flag anti-aliasing includes edge-smoothing pixels in the count when you need maximum strictness.

Zoom

Use − / + to zoom, Fit to reset to the window, or 1:1 for actual pixel size. The view scrolls when zoomed in — handy for inspecting fine detail on dense pages.

Measure tool

In Overlay and Pixel-diff views, drag on the page to measure a distance. The readout shows the length plus the horizontal and vertical components in plain language. Click once to clear the measurement.

Text-position table

Below the image, every shared text run is listed with its shift expressed as Horizontal (“12px right” / “left” / “aligned”), Vertical (“up” / “down”), and Total shift. Set the Flag shifts > N px value to highlight rows whose movement exceeds your tolerance.

Report tab — pass or fail

The Report tab rolls every page up into a single verdict.

  1. Set your pass criteria — the defaults are content ≥ 99%, pixels ≤ 2%, and max offset ≤ 3px.
  2. Click Compare all pages. Progress is shown as each page is processed.
  3. Read the overall verdict (✓ PASS / ✗ FAIL) and the per-page table.

The table lists each page's content match, pixels-different, max offset, and PASS/FAIL result. Pages that exist on only one side are marked missing. Click any row to jump straight to that page in the Layout tab for a closer look.

Tuning the verdictA page can pass even with a small visual change if it's within your pixel threshold. Tighten pixels ≤ to make the report stricter.

Exporting results

After running a full comparison, use the Export menu in the Report tab. Three formats are available:

FormatBest forContents
HTML reportSharing / archiving · print to PDFStandalone page with the verdict, the metrics table, and every page's annotated A/B images plus its change list.
JSONAutomation / recordsMachine-readable metrics, thresholds, and per-page pass/fail.
CSVSpreadsheetsPer-page metrics table.

The exported HTML report is self-contained — open it in any browser, or use your browser's Print → Save as PDF to produce a shareable, dated record.

Edge cases & notes

When a page is unusual, the tool flags it with an amber note rather than failing silently.

SituationWhat happens
Different page countsNavigation covers the larger count; extra pages show a “exists only in A/B” note and a placeholder on the missing side.
Different page size / aspectSide B is scaled to fit A and centred (letterboxed); a note explains that reported offsets may look large as a result.
Scanned / image-only pageA “no selectable text layer” note appears. The pixel diff still works, but there's no text diff or position table for that page.
Purely visual changeChanges with no text delta (recoloured header, moved rule, chart graphics) are caught by the pixel diff and by jump-to-change.

Tips & FAQ

Are my documents uploaded anywhere?

No. All parsing, rendering, and comparison happen locally in your browser. Nothing leaves your device.

Why does a page show 100% content match but still fail?

Its text is identical but a visual or positional difference exceeded a threshold — check the Layout tab's pixel diff and position table.

The offsets on one page are huge — is that a real problem?

If that page carries a letterbox note, its size differs from the original, so offsets include the scaling. Compare like-sized pages for meaningful position deltas.

How do I get a single shareable file?

Run Compare all pages, then Export → HTML report, and print it to PDF.
